# ADR 0002: Procedural Web Audio Synthesis and Adaptive Loop Architecture

- **Статус**: Прийнято
- **Дата**: 2026-11-09
- **Контекст**: selection_criteria/v10, product_criteria/v10

## Контекст та Проблема

У 2D стратегії Tower Defense звуковий супровід та швидкість симуляції є критичними для сприйняття бою.
Зберігання десятків аудіофайлів (WAV/MP3) збільшує розмір клієнтського бандла та створює ризики затримок відтворення.
Крім того, при підвищенні швидкості гри (1x / 2x) або при просадках FPS часовий крок симуляції (`dt`) не повинен дестабілізувати переміщення снарядів і колізії ворогів.

## Прийняті рішення

1. **Чистий процедурний синтез через Web Audio API (`audio.ts`)**:
   - Жодних статичних аудіофайлів у бандлі: постріли лазерів, вибухи, алерти хвиль генеруються за допомогою `OscillatorNode`, експоненційних кривих частоти (`exponentialRampToValueAtTime`) та генератора шуму для вибухів.
   - Незалежний контроль майстер-гучності та миттєве вимкнення звуку при згортанні вкладки (`visibilitychange`).

2. **Адаптивний часовий крок симуляції (`engine.ts`)**:
   - Симуляція `update(dt)` використовує обмежений часовий крок (`dt = Math.min(dt, 0.1)`), щоб уникнути стрибків через колізійні бар'єри при підвисаннях браузера.
   - Окремий реактивний контролер `state.svelte.ts` транслює зміни швидкості без модифікації внутрішньої сітки координат.

3. **Стійкість рендерингу та версіонування**:
   - Додано перехоплення помилок клієнта (`hooks.client.ts`) та автоматичне відновлення після свіжих деплоїв (`staleBuild.ts`).
   - Усі сторінки захищені межею помилок `<svelte:boundary>` з компонентом `ErrorFallback.svelte`.

## Наслідки

- Нульовий оверхед мережевого трафіку на завантаження аудіо.
- Стабільні колізії та передбачувана поведінка снарядів при швидкостях 1x / 2x.
- Надійність інтерфейсу при можливих runtime збоях Canvas або WebGL.
